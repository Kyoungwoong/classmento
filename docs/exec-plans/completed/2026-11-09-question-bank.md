# 질문 은행 (questionbank)

## 목표
관리자가 2단계 카테고리·태그·난이도·직무로 면접 질문을 관리하고 CSV로 대량 등록한다. 질문은 임베딩되어 면접(ADR 0005)의 기술·인성·혼합 선택과 경험 기반 kNN 검색의 재료가 된다.

## 범위 (PR 4개)
- A: 카테고리·태그 (도메인·V5·API)
- B: 질문 (도메인·V6·검색·임베딩·시드)
- C: 관리자 화면
- D: CSV 등록

## 단계
- [x] A 카테고리·태그 (도메인 TDD, V5 시드 5·23, 관리자 API)
- [x] B 질문 (도메인 TDD, V6 시드 46, 관리자 API·검색·페이지, 임베딩 저장·기동 시 채우기, 전역 kNN)
- [x] C 관리자 화면 (공통 컴포넌트 6개, 메뉴·회원 이동, 카테고리·질문 목록·폼, 질문 하나 조회 API)
- [x] D CSV — D1 백엔드(파서·가져오기 API, PR #12) / D2 업로드 화면(형식·카테고리 오류 한 번에)

## 결정 로그
- 2026-11-09: 카테고리는 2단계로 고정한다(사용자 결정). 삭제 대신 숨김으로 처리해 질문 기록을 보존한다.
- 2026-11-09: CSV에 없는 카테고리는 오류로 처리한다(오타로 카테고리가 생기지 않게). 없는 태그는 새로 만든다.
- 2026-11-09: 시드 행에 `seeded`를 두고, 통합 테스트는 seeded가 아닌 행만 지운다(기본 카테고리를 테스트마다 다시 넣지 않게).
- 2026-11-09: 태그 "없으면 만들기"는 트랜잭션 없이 처리하고, 유니크 충돌이 나면 기존 것을 다시 읽는다.

## 후속 (PR #10 리뷰에서 나온 것)
- 카테고리 이름을 바꾸면 그 아래 질문 임베딩이 낡는다(임베딩 문장에 카테고리 이름이 들어감) → 이름 변경 시 해당 질문 임베딩 비우기 + 채우기 작업
- 로컬 해시 임베딩으로 만든 벡터는 실제 키를 넣은 뒤에도 남는다 → `embedding_model` 컬럼으로 모델이 다르면 다시 만들기
- 기동 시 채우기는 동기. 질문이 많아지면 TaskExecutor로 비동기화
