# ADR 0008: 꼬리질문은 새 면접의 옵션, 인성은 제외

- 상태: 채택 (2026-11-10)
- 대체: [ADR 0005](0005-interview-tabs.md)의 "꼬리질문을 경험 기반 안에서 쓸지는 면접 기능을 만들 때 정한다"(미룬 결정)
- 이어받음: [ADR 0004](0004-interview-modes.md)의 지연 목표(답변 → 다음 질문 8초)와 종료 조건(최대 깊이 또는 AI `done`)

## 결정
- 꼬리질문은 탭이 아니라 **새 면접의 옵션**이다: 질문 하나에 **없음 / 한 번 / 두 번**(최대), 기본 한 번.
- **인성 면접에는 없다.** 경험 기반·기술·혼합에서 쓸 수 있고, 혼합에서는 기술 질문에만 붙는다.
- AI가 답이 충분하다고 보면(`done`) 최대보다 일찍 멈춘다. 생성이 실패하거나 늦어도 면접은 멈추지 않는다(그 질문은 꼬리 없이 넘어간다).
- 꼬리질문은 **직전 답변에 실제로 있는 말**(`basis`)을 근거로만 만든다. 서버가 그 구절이 답변 안에 있는지 확인한다.
- 질문 번호(seq)는 고정 식별자로 남기고 꼬리는 뒤에 붙인다. 화면 순서는 (본 질문, 깊이)로 정한다.

## 이유
- 실제 면접은 정해진 질문 뒤에 "왜 그렇게 했나요?"처럼 답에서 파고든다. 탭을 늘리지 않고 모든 기술 연습에 붙이는 것이 가장 실전에 가깝다(사용자 선택).
- 인성 질문은 꼬리보다 STAR 구조 연습이 목적이고, 사용자가 제외를 골랐다.
- 질문 하나에 최대 두 번이면 질문 7개라도 21문항 안이라 시간이 예측된다.

## 결과
- `InterviewQuestion`에 parentSeq·rootSeq·depth·followUp 상태, `InterviewSession`에 maxFollowUps(V10).
- 답변 처리 순서가 STT → 꼬리 판단 → 평가로 바뀐다. 다음 질문이 평가에 밀리지 않게 실행기를 나눈다.
- 프롬프트 `follow-up-question.v1`(LLM 호출이 답변마다 하나 늘어난다 — 크레딧 설계 때 반영).
- 리포트 평균은 꼬리 답변도 같은 비중으로 넣는다. 일관성 기준(ADR 0004)은 다음 버전으로 미룬다.
