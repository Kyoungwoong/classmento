# ADR 0004: 면접 유형 4가지

- 상태: 채택 (2026-11-08)
- 대체: 기존 "기술/인성 2유형, 둘 다 이력서 기반" 설계, "꼬리질문은 범위 밖"

## 결정
| # | 유형 (`InterviewMode`) | 이력서 | 질문 출처 | 진행 방식 |
|---|---|---|---|---|
| 1 | `TECH` 기술 | 불필요 | 사용자가 고른 **직무·연차 + 기술 스택 + CS 포함 여부** → **질문 은행** 필터·kNN + AI 변형 | 질문 N개를 미리 생성 |
| 2 | `RESUME_TECH` 이력서 기반 기술 | **필수** | **이력서 청크 RAG** + 이력서 기술과 맞는 질문 은행 질문(나중에 JD 매칭 추가) | 질문 N개를 미리 생성 |
| 3 | `DEEP_DIVE` 꼬리질문 | 선택 | 시작 주제 1개: 이력서 프로젝트 또는 고른 기술. 이후 질문은 **직전 답변으로 AI가 실시간 생성** | 한 주제를 3~5단계로 파고든다 |
| 4 | `BEHAVIORAL` 인성 | 불필요 | **공통 인성 질문만**(질문 은행의 인성 카테고리: 자기소개, 지원동기, 갈등, 실패, 성장 …) | 질문 N개를 미리 생성 |

## 이유
- 사용자 상황이 다르다.
  - 이력서가 없거나 특정 기술만 연습하고 싶다 → 1
  - 실제 지원 대비 → 2
  - 압박·심층 대비 → 3
  - 인성 대비 → 4
- 꼬리질문은 질문을 미리 만들 수 없고(답변에 따라 달라짐), 응답 지연 요구도 달라서 별도 유형으로 분리했다.
- 질문 은행이 1·2·4의 공통 기반이다. 그래서 다음 구현 순서는 **질문 은행**이 먼저다.

## 결과 / 설계 영향
- **질문 은행** `question_bank`
  - 필드: category(`CS`/`STACK`/`ROLE`/`BEHAVIORAL`), job_role, level(신입/주니어/미들/시니어), tags(기술 스택), text, intent, 평가 포인트, embedding
  - 관리자가 등록하고, 등록할 때 임베딩한다.
- **면접 세션** `interview_session`
  - 필드: mode, resume_id(nullable — `RESUME_TECH`만 필수), 선택 조건(`config` jsonb: 직무, 연차, 스택, CS 여부, 질문 수, 시작 주제)
- **질문** `question`
  - 필드: parent_question_id(꼬리질문이 어느 답변에서 나왔는지), depth(0=시작 질문)
- **꼬리질문 지연 목표:** 답변 업로드 → STT → 다음 질문까지 **8초 이내**. 넘으면 "다음 질문을 고르고 있어요"를 표시한다.
- **꼬리질문 종료 조건:** 최대 깊이에 도달하거나, AI가 "충분히 파악함"으로 판단하면 끝난다(출력 JSON에 `done` 필드).
- **프롬프트:** 유형별로 분리한다(아래). 기존 `question-generation.v1`은 `RESUME_TECH` 전용으로 바뀐다.
- **홈 화면 문구**("이력서 한 장으로 실전 면접을 준비해요")는 그대로 둔다(사용자 결정, 2026-11-08). 대표 시나리오는 이력서 기반이고, 다른 유형은 유형 선택 화면에서 고른다.
- **크레딧(ADR 0003):** 1·2·4는 세션 시작 시 차감한다. 3은 턴마다 LLM을 호출하므로 단가를 따로 매기거나 최대 턴을 제한한다.
