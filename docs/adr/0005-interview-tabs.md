# ADR 0005: 면접 탭 4개 — 경험 기반 · 기술 · 인성 · 혼합

- 상태: 채택 (2026-11-09)
- 대체: [ADR 0004](0004-interview-modes.md)의 유형 정의(기술 / 이력서 기반 기술 / 꼬리질문 / 인성)

## 결정
| 탭 | 코드 | 이력서 | 질문 출처 |
|---|---|---|---|
| 1. 경험 기반 면접 | `EXPERIENCE` | **필수**(없으면 탭 숨김) | 이력서에서 뽑은 **경험(Experience) 목록**을 배너(제목 + 요약)로 보여주고, 사용자가 하나를 고르면 **그 경험과 관련된 기술·CS 질문**을 한다(경험 원문·기술 + 경험 벡터 RAG) |
| 2. 기술 면접 | `TECH` | 선택 | 질문 은행의 기술 카테고리(Language · Framework · CS). 이력서가 있으면 이력서의 기술로 범위를 좁힌다 |
| 3. 인성 면접 | `BEHAVIORAL` | 불필요 | 질문 은행의 인성 카테고리 |
| 4. 혼합 | `MIXED` | 선택 | 기술 + 인성 |

- **질문 은행**에는 Language · Framework · CS · 인성 대분류를 모두 둔다(2단계 카테고리, 태그·난이도·직무, CSV 등록).
- **꼬리질문**은 별도 탭이 아니다. 경험 기반 면접 안에서 쓸지는 면접 기능을 만들 때 정한다.

## 이유
- 실제 기술 면접은 "이 프로젝트에서 왜 그 기술을 썼나요?"처럼 경험 하나를 파고든다. 경험 단위로 고르게 하면 질문이 구체적이 되고, 사용자가 연습 범위를 직접 정할 수 있다.
- 경험 단위 벡터가 있으면 "이 경험과 관련된 CS 개념"을 질문 은행에서 kNN으로 찾을 수 있다(경험 벡터 ↔ 질문 벡터).

## 결과
- 이력서 구조화 결과의 경력·프로젝트를 **`ResumeExperience`**(resume 컨텍스트)로 저장하고, 경험마다 요약과 임베딩을 둔다.
- 기존 800자 청크(`resume_chunk`)는 이력서 전체 검색용으로 남긴다.
- 구조화 프롬프트를 v2로 바꿔 경험마다 `summary`를 받는다.
