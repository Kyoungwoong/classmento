# 제품 개요

> 실전처럼 말로 답하는 모의면접. 기술 · 이력서 기반 기술 · 꼬리질문 · 인성 4가지 유형, 피드백은 바로.

## 사용자 흐름 (MVP)
0. **회원가입/로그인** — 이메일+비밀번호, 소셜(구글·카카오, 키 설정 시). 모든 데이터는 회원에게 속한다.
1. **이력서 업로드(선택)** — PDF/DOCX(최대 20MB). 서버가 텍스트를 추출해 청크로 나누고 임베딩(벡터 검색용)한 뒤 Claude로 구조화한다. `RESUME_TECH` 유형에만 필수.
2. **파싱 결과 확인** — 경력·기술·프로젝트 목록을 보여주고, 사용자가 틀린 부분을 고친다.
3. **면접 유형 선택** — 아래 4가지 중 하나 + 유형별 조건 + 질문 수(기본 5개). 결정: [ADR 0004](../adr/0004-interview-modes.md)
4. **질문 생성** — 유형마다 질문 출처가 다르다. 각 질문에는 의도(intent)와 근거(source)가 있다.
5. **음성 답변** — 질문을 화면에 보여주고, 사용자가 녹음 버튼으로 답한다(문항당 최대 3분). 녹음 파일을 서버로 보낸다.
6. **STT** — CLOVA Speech로 텍스트 변환. 사용자는 변환 결과를 확인할 수 있다(수정은 MVP 제외).
7. **평가** — 문항별 루브릭 점수 + 잘한 점/고칠 점/답변 방향. 세션 종료 시 종합 리포트.

## 면접 유형 4가지
| 유형 | 이력서 | 고르는 것 | 질문은 어디서 |
|---|---|---|---|
| **1. 기술** `TECH` | 필요 없음 | 직무·연차, 기술 스택, CS 포함 여부 | 질문 은행(직무·연차·스택·CS 필터 + kNN) → AI가 다듬음 |
| **2. 이력서 기반 기술** `RESUME_TECH` | **필수** | 이력서 선택 (나중에 채용공고) | 이력서 청크 RAG + 이력서 기술과 맞는 질문 은행 질문 |
| **3. 꼬리질문** `DEEP_DIVE` | 선택 | 시작 주제 1개(이력서 프로젝트 또는 기술), 깊이 3~5 | 첫 질문 이후 **내 답변을 듣고 AI가 바로 다음 질문**을 만든다 |
| **4. 인성** `BEHAVIORAL` | 필요 없음 | 질문 수 | **공통 인성 질문**(자기소개·지원동기·갈등·실패·성장 …) 질문 은행 |

- 1·2·4는 질문을 미리 만들어 두고 차례로 답한다. 3은 한 질문씩 대화하듯 진행한다.
- 질문 은행은 관리자가 관리한다(직무·연차·기술 태그·카테고리·평가 포인트 + 임베딩). 1·2·4의 공통 기반이라 가장 먼저 만든다.

## 용어집
| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 회원 | `AppUser` | 이메일/소셜 계정. 역할 `USER`/`ADMIN` |
| 이력서 | `Resume` | 업로드 원본 + 추출 텍스트 + 구조화 결과(`ParsedResume`) |
| 이력서 청크 | `resume_chunk` | 이력서를 ~800자로 나눈 조각 + 임베딩 벡터(검색용) |
| 질문 은행 | `question_bank` (예정) | 관리자가 등록한 질문. 카테고리(CS/STACK/ROLE/BEHAVIORAL), 직무, 연차, 기술 태그, 평가 포인트 + 벡터 |
| 채용공고 | `job_posting` (예정) | 사용자가 지원할 공고 본문 + 벡터 |
| 크레딧 | `credit_ledger` (예정) | 유료 사용량 원장. 설계: ADR 0003 |
| 면접 유형 | `InterviewMode` | `TECH` / `RESUME_TECH` / `DEEP_DIVE` / `BEHAVIORAL` |
| 면접 세션 | `InterviewSession` | 한 번의 모의면접. 유형, 선택 조건(config), 이력서(선택), 질문 목록, 상태 |
| 질문 | `Question` | 질문 문장, intent, source, 순서. 꼬리질문은 부모 질문과 깊이(depth)를 가진다 |
| 답변 | `Answer` | 녹음 파일 참조, STT 텍스트(`Transcript`), 녹음 길이 |
| 평가 | `Evaluation` | 답변 1개에 대한 루브릭 점수와 피드백 |
| 리포트 | `SessionReport` | 세션 전체 요약(평균 점수, 강점/보완점) |

## 세션 상태
`CREATED → QUESTIONS_READY → IN_PROGRESS → EVALUATING → COMPLETED` (실패 시 `FAILED`)

## 단계별 범위
- **완료:** 회원·관리자, 이력서 업로드·구조화·청크 임베딩
- **다음:** 질문 은행(관리자) → 면접 세션 + 질문 생성(1 기술·4 인성 → 2 이력서 기반) → 녹음·STT → 평가·리포트 → 3 꼬리질문 → JD 매칭
- **이후:** 크레딧 결제(ADR 0003)
- **범위 밖:** 영상 면접, STT 결과 수정, 다국어

## 품질 기준
- 이력서 기반 질문(2, 3의 이력서 주제)은 이력서에 실제 있는 내용만 근거로 한다(환각 금지).
- 기술 질문(1)은 고른 직무·연차 수준에 맞춘다(신입에게 시니어급 설계 질문 금지).
- 평가는 반드시 답변 인용 근거를 포함한다.
- 사용자 대기 시간: 질문 생성 10초 이내, 문항 평가 15초 이내, **꼬리질문 다음 질문 8초 이내**(넘으면 진행 상태 표시).
